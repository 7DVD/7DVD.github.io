# Accessibility

Accessibility is important to 7DVD. The goal of this project is to make the website, its content, and its community as usable as reasonably possible for everyone, including people who use assistive technologies or different methods of interacting with the web.

This document describes the accessibility practices and expectations for the project, as well as how to report accessibility barriers.

## Priorities

The project aims to provide an accessible experience across the website, with particular attention to:

- Clear and readable content.
- Keyboard navigation.
- Appropriate headings and page structure.
- Descriptive links and labels.
- Sufficient color contrast.
- Accessible forms and interactive elements.
- Alternative text for meaningful images.
- Responsive layouts across different screen sizes.
- Compatibility with commonly used browsers and assistive technologies.
- Avoiding unnecessary motion, flashing, or other content that may create barriers.

Accessibility is an ongoing effort. The project does not claim complete or verified conformance with any particular accessibility standard unless explicitly stated.

## Contributor Expectations

Contributors are encouraged to consider accessibility whenever making changes to the website or its content.

When contributing user-facing changes:

- Use semantic HTML where appropriate.
- Ensure interactive elements can be accessed using a keyboard.
- Provide descriptive text for links and buttons.
- Provide alternative text for meaningful images.
- Do not rely solely on color to communicate information.
- Maintain readable text and sufficient visual contrast.
- Ensure content remains usable on different screen sizes.
- Avoid unnecessary animations or rapidly changing content.
- Keep headings and page structure logical.
- Test changes in a browser before submitting a pull request when applicable.

Contributors should mention relevant accessibility considerations in their pull request when a change affects the user interface or user experience.

## Reporting Accessibility Issues

If you encounter an accessibility barrier, please report it through GitHub Issues.

When reporting an issue, please provide as much useful information as possible, including:

- The affected page or URL.
- What you were trying to accomplish.
- What happened.
- What you expected to happen.
- Browser and version.
- Operating system and version.
- Device, if relevant.
- Assistive technology being used, if applicable.
- Any steps that reproduce the problem.

Screenshots or recordings are welcome but are not required.

You do not need to disclose any disability or personal medical information when reporting an accessibility issue.

## Severity

Accessibility issues may be prioritized based on how significantly they affect a user's ability to use the website.

Examples include:

- **Critical:** A major function is completely inaccessible and there is no reasonable alternative.
- **High:** A significant function is difficult or impossible to use for some users.
- **Moderate:** A barrier makes a task substantially more difficult but a workaround is available.
- **Low:** A minor issue that causes inconvenience without preventing access to the content or functionality.

Maintainers may determine the severity of an issue during review. Reporters do not need to assign a severity level.

## How We Respond

Accessibility reports will be reviewed as part of the project's normal issue-management process.

Depending on the issue, maintainers may:

1. Confirm the reported barrier.
2. Request additional information if necessary.
3. Investigate possible solutions.
4. Provide a workaround where practical.
5. Implement and test an appropriate fix.
6. Close the issue once the problem has been addressed or otherwise resolved.

Response and resolution times may vary depending on the complexity and priority of the issue.

## Ownership and Maintenance

Accessibility is maintained as part of the normal development and content-maintenance process.

The project maintainer is responsible for:

- Reviewing reported accessibility issues.
- Considering accessibility when reviewing contributions.
- Prioritizing accessibility improvements where appropriate.
- Keeping this document reasonably up to date.
- Updating accessibility practices as the project changes.

This document may be updated when the project's accessibility practices, supported environments, or reporting process change.

## Supported Environments

The website is intended to work across commonly used modern browsers and devices, including:

- Desktop and laptop computers.
- Mobile phones and tablets.
- Keyboard and mouse input.
- Touch input.
- Common modern web browsers.

The project does not guarantee compatibility with every browser, device, operating system, or assistive technology combination.

Accessibility should be considered across different environments, and reports identifying compatibility problems are welcome.

## Known Limitations

The project may contain accessibility barriers that have not yet been identified or resolved.

Known limitations will be documented through GitHub Issues where practical.

If you encounter a barrier that is not already documented, please report it so that it can be investigated.

The absence of a documented limitation should not be interpreted as a guarantee that the website is fully accessible.

## Feedback and Improvements

Accessibility is an ongoing process, and feedback is welcome.

If you have suggestions for improving the accessibility of the website, its content, or this accessibility statement, please open a GitHub Issue or start a GitHub Discussion.

When reporting an active accessibility barrier, please use the reporting process described above so that the issue can be properly tracked.

Thank you for helping make 7DVD more accessible and usable for everyone.
