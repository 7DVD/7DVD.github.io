# Security Policy

## Overview

Security is important to 7DVD.

This project may contain software, documentation, educational material, and other content related to programming, cybersecurity, and security research.

If you discover a potential security vulnerability affecting this repository or the associated website, please report it responsibly and privately.

## Supported Versions

This project is continuously maintained and does not currently follow a traditional versioned release cycle.

Security reports concerning the current version of the project are welcome.

| Version | Supported |
| ------- | --------- |
| Current | Yes       |
| Older versions | No    |

## Reporting a Vulnerability

Please do not report security vulnerabilities through public GitHub Issues or Discussions.

If available, use GitHub's private vulnerability reporting feature to submit your report.

When reporting a vulnerability, please provide as much relevant information as possible, including:

- A clear description of the vulnerability.
- The affected page, component, file, or feature.
- Steps required to reproduce the issue.
- The potential security impact.
- Screenshots, logs, or proof-of-concept material when appropriate.
- Any suggested mitigation or fix, if you have one.

Please do not include passwords, authentication tokens, personal information, or other sensitive information unless it is necessary to demonstrate the vulnerability.

## What Happens After a Report

After receiving a security report, the report will be reviewed to determine whether it represents a valid security issue.

Depending on the situation, the following steps may be taken:

1. The report will be reviewed and investigated.
2. Additional information may be requested if necessary.
3. The issue may be reproduced and its potential impact assessed.
4. An appropriate fix or mitigation may be developed.
5. The affected component may be updated.
6. The report may be closed if the issue is determined not to be a security vulnerability.

Response and resolution times may vary depending on the complexity and severity of the issue.

## Responsible Disclosure

Please allow reasonable time for a reported vulnerability to be investigated and, where appropriate, resolved before publicly disclosing detailed information.

Responsible disclosure helps protect users and gives maintainers an opportunity to address security issues properly.

Please do not publicly disclose sensitive vulnerability details, exploit instructions, credentials, or other information that could be used to compromise users or systems.

## Security Research

Security research, experimentation, and educational contributions are welcome when performed responsibly and with appropriate authorization.

Do not use this project to:

- Obtain unauthorized access to systems, accounts, networks, or services.
- Access, modify, or disclose private information without permission.
- Distribute malware or intentionally harmful code.
- Attempt to compromise systems that you do not own or have permission to test.
- Use project content to facilitate unauthorized or malicious activity.

Only test systems that you own or have explicit permission to test.

## Out of Scope

The following generally do not constitute security vulnerabilities by themselves:

- General feature requests.
- Cosmetic or design issues.
- Spelling or documentation errors.
- Issues with third-party services that are not controlled by this project.
- Automated scanner results without a demonstrated security impact.
- Issues that require physical access to a user's device.
- Social engineering attempts against individuals.

These issues may still be useful and can generally be reported through GitHub Issues or Discussions where appropriate.

## Third-Party Dependencies

Vulnerabilities in third-party software, services, libraries, or dependencies should generally be reported to their respective maintainers.

If a third-party vulnerability directly affects this project, please include relevant details when submitting a report.

## Contact

For security-related matters, please use GitHub's private vulnerability reporting functionality when available.

If private vulnerability reporting is not available, contact the project maintainer through a private GitHub communication channel.

Please do not publicly post sensitive security information in Issues, Discussions, Pull Requests, or other public areas of the repository.

Thank you for helping keep 7DVD and its community secure.
