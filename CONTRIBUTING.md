# Contributing to 7DVD

Thank you for your interest in contributing to 7DVD.

This repository contains the source for the 7DVD website and serves as a space for projects, experiments, documentation, learning resources, and technical content.

Contributions, suggestions, corrections, and constructive feedback are welcome.

## Before You Contribute

Before opening an issue or pull request, please:

- Search existing issues and pull requests to avoid duplicates.
- Read the relevant documentation.
- Make sure your contribution is related to the purpose of the repository.
- Follow the project's Code of Conduct.
- Avoid submitting changes that are unrelated to the project.

## Ways to Contribute

There are several ways you can contribute:

- Report bugs or broken functionality.
- Suggest improvements or new features.
- Fix spelling, grammar, or documentation issues.
- Improve existing documentation.
- Submit improvements to the website.
- Add useful examples or educational content.
- Improve accessibility, performance, or compatibility.
- Review and provide constructive feedback on pull requests.
- Share ideas that could improve the project.

You do not need to be an expert to contribute. If you notice something that could be improved, feel free to open an issue and explain your idea.

## Opening an Issue

Before opening an issue, check whether a similar issue already exists.

When creating an issue, please provide:

- A clear and descriptive title.
- A detailed explanation of the issue or suggestion.
- Relevant context and examples.
- Steps to reproduce the problem, when applicable.
- Screenshots, logs, or other useful information when appropriate.
- Your expected result and what actually happened, if reporting a bug.

A well-documented issue makes it much easier to understand and address the problem.

## Pull Requests

Pull requests are welcome when they provide a meaningful improvement to the project.

Before submitting a pull request:

1. Make sure your changes are relevant to the repository.
2. Review your changes carefully.
3. Test your changes when applicable.
4. Check for spelling, formatting, and broken links.
5. Keep the pull request focused on a specific change.
6. Avoid including unrelated modifications.
7. Provide a clear description of what you changed and why.

### Pull Request Description

Please explain:

- What you changed.
- Why the change was necessary or useful.
- How you tested the change.
- Any relevant limitations or considerations.

For larger changes, it is recommended to open an issue or discussion first so the idea can be discussed before significant work is done.

## Website and Content Contributions

When contributing website content, documentation, tutorials, or other written material:

- Keep the information accurate and useful.
- Use clear and understandable language.
- Provide sources or references when appropriate.
- Avoid unnecessary duplication.
- Respect copyright and licensing.
- Do not submit content copied from other sources without permission or appropriate attribution.
- Keep content relevant to the purpose of the website.

## Code Contributions

When contributing code:

- Follow the existing project structure and conventions where practical.
- Keep code readable and maintainable.
- Avoid unnecessary dependencies.
- Do not introduce malicious or intentionally harmful code.
- Test your changes before submitting them.
- Keep commits and pull requests focused where possible.

If the repository already has an established style or implementation pattern, try to follow it rather than introducing an entirely different approach without discussion.

## Security-Related Contributions

This project may contain cybersecurity, ethical hacking, programming, and security-related material.

Security-related contributions must be made responsibly.

Do not submit:

- Malware or malicious payloads.
- Stolen credentials or private information.
- Real-world personal data without permission.
- Backdoors or intentionally malicious functionality.
- Instructions intended to facilitate unauthorized access or abuse.
- Exploits targeting systems without authorization.
- Content that encourages illegal or harmful activity.

Security demonstrations and educational examples should be designed and presented for legitimate learning and authorized testing.

If you discover a security vulnerability affecting this repository or website, please report it privately rather than publicly posting sensitive details.

## Commit Messages

Use clear and meaningful commit messages.

For example:
```

Fix broken navigation link

```

```

Improve documentation for project setup

```

```

Add accessibility improvements to homepage

```

Avoid vague messages such as:
```

update

```

```

changes

```

```

stuff

```

## Review Process

All pull requests may be reviewed before being merged.

Reviewers may request:

- Changes to the implementation.
- Additional documentation.
- Tests or verification.
- Clarification about the proposed change.
- Changes to keep the contribution consistent with the project.

Please treat review feedback as part of the collaboration process.

Disagreement is allowed and encouraged when it leads to better technical decisions. Keep discussions focused on the contribution rather than the person making it.

## Documentation and Spelling Fixes

Small improvements are welcome.

If you find:

- A spelling mistake.
- A broken link.
- Incorrect documentation.
- Outdated information.
- A confusing explanation.
- A formatting problem.

You can submit a pull request directly without opening a separate issue, provided the change is straightforward.

## Large Changes

For significant changes, please open an issue or GitHub Discussion before submitting a large pull request.

This is especially useful for:

- Major website redesigns.
- New sections or features.
- Significant changes to the project's structure.
- New dependencies.
- Changes that affect the overall direction of the project.

Discussing larger changes beforehand helps avoid unnecessary work and allows ideas to be reviewed before implementation.

## Keep Contributions Focused

A pull request should generally address one main problem or improvement.

For example, avoid combining:

- A website redesign.
- Documentation changes.
- Dependency updates.
- Unrelated bug fixes.

into a single pull request.

Keeping changes focused makes them easier to review, test, and maintain.

## Questions and Discussions

If you are unsure about something, you are welcome to start a GitHub Discussion.

When asking a question, provide enough information for others to understand what you are trying to accomplish.

Constructive questions and ideas are encouraged.

## Code of Conduct

All contributors are expected to follow the project's Code of Conduct.

Please make sure you are familiar with it before participating in the project.

## Attribution

By submitting a contribution, you confirm that:

- You created the contribution yourself or have the necessary permission to submit it.
- You have the right to submit the contribution under the project's applicable license.
- Your contribution does not knowingly violate another person's copyright or intellectual property rights.

Please provide appropriate attribution when using third-party resources.

## Final Note

There is no requirement to be an experienced developer to contribute.

If you have an idea, find a problem, notice something that could be improved, or simply want to help, feel free to participate.

Thank you for contributing to 7DVD.
